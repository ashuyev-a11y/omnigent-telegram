# Техзадание: omnigent-telegram

Telegram-бот — пульт управления оркестратором Omnigent. Не интерфейс для
сложного кодинга (для этого есть веб-UI Omnigent), а способ отдать короткую
задачу с телефона и получить результат.

Язык: Python 3.12. Библиотека: `python-telegram-bot` (v21+, async).

## Главный принцип

**Один Telegram-чат = один проект.** Проект задаёт рабочую директорию, в
которой запускается оркестратор. Никакого определения проекта по тексту
сообщения — контекст задан тем, откуда пришло сообщение. Сообщение из
неизвестного чата игнорируется.

## Поведение

1. Пользователь пишет в чат текст задачи (обычное сообщение, без команды).
2. Бот проверяет: чат есть в конфигурации, автор в списке разрешённых.
   Если нет — молча игнорирует (никакого ответа, чтобы не подтверждать
   существование бота посторонним).
3. Бот запускает в рабочей директории проекта:
   `omnigent run <bundle_path> -p "<текст задачи>"`
4. Первая строка вывода `omnigent run` имеет вид
   `Omnigent session: http://127.0.0.1:8000/c/<id>` — бот извлекает URL и
   сразу отправляет его в чат как подтверждение, что задача принята.
5. По завершении процесса бот отправляет в чат финальный вывод оркестратора
   (весь stdout без первой строки с URL).
6. Если процесс завершился с ненулевым кодом или упал — бот отправляет
   сообщение об ошибке с последними строками stderr.

## Команды

- `/start` — краткая справка и имя привязанного к чату проекта.
- `/status` — показать, выполняется ли сейчас задача в этом чате, и URL её
  сессии.
- `/cancel` — прервать текущую задачу этого чата (завершить подпроцесс).

## Конфигурация

Файл `config.yaml` рядом с ботом (путь задаётся переменной окружения
`OMNIGENT_TG_CONFIG`, по умолчанию `./config.yaml`):

```yaml
bundle_path: /home/deploy/omnigent-agents/orchestrator
timeout_seconds: 1800

projects:
  - name: orchestrator
    chat_id: -1001234567890
    workdir: /home/deploy/omnigent-workspaces/orchestrator-repo
    allowed_user_ids: [123456789]
```

Токен бота берётся **только** из переменной окружения `TELEGRAM_BOT_TOKEN`.
Никогда не из config.yaml, никогда не из аргументов командной строки.

В репозиторий положить `config.example.yaml` с вымышленными значениями.
Реальный `config.yaml` — в `.gitignore`.

## Требования к реализации

**Одна задача на чат одновременно.** Если в чате уже выполняется задача,
новое сообщение получает ответ «занят, задача выполняется» со ссылкой на
текущую сессию. Не ставить в очередь, не запускать параллельно.

**Не блокировать бота.** Подпроцесс запускать через
`asyncio.create_subprocess_exec`, а не `subprocess.run`. Пока задача идёт,
бот должен отвечать на `/status` и `/cancel` в этом и других чатах.

**Таймаут.** По истечении `timeout_seconds` подпроцесс завершается, в чат
уходит сообщение о таймауте со ссылкой на сессию.

**Длинные ответы.** Лимит сообщения Telegram — 4096 символов. Ответы длиннее
резать на несколько сообщений по границам строк, не по символам.

**Никаких секретов в логах.** Логировать факт запуска, chat_id, код возврата,
длительность. Не логировать текст задачи целиком и никогда не логировать
переменные окружения.

**Текст задачи не интерпретировать.** Передавать его в `-p` как отдельный
аргумент списка при вызове подпроцесса, никогда не через shell-строку.
Аргумент не экранировать вручную и не подставлять в `shell=True`.

## Структура репозитория

```
bot.py                  # точка входа, обработчики
runner.py               # запуск и контроль подпроцесса omnigent run
config.py               # загрузка и валидация config.yaml
config.example.yaml
requirements.txt
README.md               # установка, systemd-юнит, получение chat_id
.gitignore
```

## Тесты

`test_config.py` — загрузка корректного конфига, отказ при отсутствии
обязательных полей, отказ при дубликате chat_id.

`test_runner.py` — извлечение URL сессии из первой строки вывода, нарезка
длинного текста на части по границам строк, поведение при ненулевом коде
возврата. Подпроцесс в тестах подменять, реальный `omnigent run` не вызывать.

Тесты должны проходить без токена, без сети и без запущенного Omnigent.

## Чего в этой версии НЕ делать

Approval-карточек и кнопок. Продолжения диалога с сессией. Параллельных
задач. Доступа к Supabase, Vercel и любым ключам проектов. Автоматического
определения проекта. Вебхуков — только long polling.

## Критерии приёмки

- `python -m pytest -q` проходит полностью.
- Бот запускается с примером конфига и корректным токеном, отвечает на
  `/start`.
- Сообщение из чата, которого нет в конфиге, не вызывает никакого ответа.
- Сообщение от пользователя не из `allowed_user_ids` не вызывает ответа.
- В коде нет `shell=True` и нет конкатенации пользовательского текста в
  команду.
- `config.yaml` отсутствует в репозитории и указан в `.gitignore`.
